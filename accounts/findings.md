# 账户回访、复用与支付观察

快照截止：2026-09-16 15:10（北京时间）。当前结果使用全历史、入口 referrer 或 UTM 的同一主 cohort。以下分母是可关联账户，不是所有访客；只统计可观察 Web 行为。

## 最值得进入报告的三项结论

1. **注册后发生首次使用，并未自然形成再次使用。** 3,121个可关联账户中，累计2,458个出现“注册信号后提交消息”的V1代理；首24小时后具有完整7日观察的2,864个账户中，120个再次访问（4.19%，95%区间3.52%–4.99%），52个在独立Visit再次提交（1.82%，1.39%–2.37%）。因此在修复入口/注册承接之后，下一项独立目标应是让首次任务有可继续的下一步，并方便回到原任务。此处不等于已生成或下载结果。
2. **首日从一次提交走到进一步交互，是值得验证的体验候选。** 首24小时仅一次提交的1,783人，随后7日27人再次提交（1.51%）；两次以上的649人，24人再次提交（3.70%）。在同入口需求×同周、每组至少5人的12个共同分层中（2,398人），标准化后仍为1.57%和3.87%，差2.31个百分点，近似95%区间0.64–3.97个百分点。建议测试原任务继续编辑、结果后的明确下一步和任务恢复，同时补齐生成/下载信号与错误/重试护栏。高意愿、任务复杂度、重试等仍可能解释一部分差异，不能以“多发一条消息”作为成功目标。
3. **商业分析应优先定位价格/结账链路。** 全生产站41条purchase对应41个交易键，无重复、缺键或属性冲突。20个事件能用唯一一致link归到19账户；另19个没有截止时点前link、2个存在多link。严格映射、全部候选link、当前session身份三种检查都没有与MeiGen账户交集；当前session维度共22个付款事件关联账户。可以报告“未在本MeiGen账户cohort观察到匹配的purchase”，不能报告实际付费率为零。已识别MeiGen账户中177个出现付费意图信号，价格/套餐/结账仍有可分析的推进机会。

14日完整观察账户为2,143，回访113（5.27%），再次提交55（2.57%）；分母比7日更早，不能将两者直接比较为同一批人的留存变化。需求和周明细、分子分母及Wilson区间均在`summary.json`。去水印、视频编辑和模型入口的当前已识别账户缺完整7日观察，在相应回访表不填零。

功能扩展目前主要是主动方向选择的证据：7日成熟账户中4个选择新的composer方向，10个浏览另一类具体入口；这些不是跨功能任务成功或下载。建议将这一模块作为再使用路径探索，避免用稀疏样本推导广泛的交叉销售结论。

## 数据与身份核验

- 排除4个前置事件异常Visit后，34,359次合格入口；3,332次Visit有当次结束前的唯一一致账户映射，共3,121账户，14次Visit身份冲突。只有1个账户在最早锚点入口时已识别，其余为同Visit后识别。
- 账户首次锚点来源构成：明确referrer 2,832；UTM-only 218；认证回流携带UTM 69；其他referrer+UTM 2。敏感性表分别展示这些来源，不将69个认证回流账户直接解释为新获客。
- 44,738条历史事件及44,738个唯一event_id；属性冲突0、重复属性键0。另核对3,949个完整Visit起止。
- 锚点Visit的11,493条识别前事件用于同Visit回溯恢复；它们不会改变“入口时已识别”标记。只按link生效后计算首日提交次数的敏感性结果仍保持一致：0/1/2+次组7日再提交率约0.23% / 1.51% / 3.77%。
- 非锚点的历史和后续事件仅在唯一账户映射已生效后归属。回访起点使用实际Visit首事件，不能用首次识别事件伪造新Visit。
- 账户互斥矩阵加总为3,121。累计阶段分别保留注册、提交、注册后使用、再次使用和付费意图标记，展示阶段排序不作为所有人实际经过的漏斗。

执行入口为`../extract_accounts.py`与`../analytics_accounts.py`；动态执行需传同一`--end`，可使用`--data-dir`和`--output-dir`写入独立generation。查询与原始响应见`extract/`。`summary.json`和`account_analysis.json`为同一正式结果；旧传输试跑数据已隔离至`superseded_transport_probes/`，不用于报告。
